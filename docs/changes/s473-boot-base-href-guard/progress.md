## 2026-10-29T05:40Z — implementation (tests went green; red-first commit was refused by the hook)

- The hook runs the bootstrap slices whenever `compiler/self-host-v2/` is staged, so a commit of
  the 27-red test file alone fails it (no `--no-verify`). Tests and implementation land together;
  the red count above was measured on base before any implementation edit.
- Gap id: per the coordinator, the #1635 id `g-boot-base-href-from-data-retargets-server-calls-s473`
  (not the one first suggested). #1635 is not on main, so this branch adds the entry (its text +
  a Resolved paragraph) — keep both texts at merge.
- Governing SPEC sentence written (§5.2, new bullet after rule 3's provenance), marked PA ruling
  S473: *"A `<base>` (tag compared case-insensitively) whose `href` (any case) is not a static
  string — … — SHALL be a compile error (E-ATTR-BASE-HREF). … Every runtime path that writes a
  `<base>`'s `href` from data SHALL refuse the write (fail closed). Whatever the source of a
  `<base>` — a static one included — the runtime SHALL address its own requests (a
  server-function call, §12.3) by an absolute URL resolved against the document's own URL, never
  against its base URL, and SHALL NOT send such a request to any other origin; where the
  document's URL cannot serve as a base (`about:blank`), it SHALL make no request …"*
  + §34 row E-ATTR-BASE-HREF. severity.scrml and SPEC-INDEX regenerated by script.
- `analyze.scrml` `resolveHtml`: one new arm beside E-STYLE-VALUE-NOT-STYLE (the #1635 shape; no
  new reader).
- `runtime.js`:
  - `attr`: a `<base>` `href` / `*:href` is never written (removed, reported without the value,
    the value fn never run); `srcdoc` is never written from data (the wall behind §5.2 rule 2).
    Helpers are named `isBaseElement` / `isBaseHrefName` so they don't collide with #1635's
    `isHrefName` at merge.
  - `call`: `fetch(ownOriginUrl(route.path), init)` — resolved against `location.href`, origin
    checked; throws (→ Unreachable, no request) off-origin or when the document URL can't be a
    base; no `location` and no `document` → the path as given.
- Network calls the bootstrap runtime makes (the full list; grep of `fetch` / `WebSocket` /
  `EventSource` / `sendBeacon` / `XMLHttpRequest` / `location` / dynamic `import(` over
  `compiler/self-host-v2/**` non-test): exactly ONE — `rt.call`'s `globalThis.fetch` (server-function
  call). No route/navigation fetch, no channel socket, no EventSource in the bootstrap runtime
  (`server-runtime.js`'s `fetch(request)` is the server's handler, not a request). impl#1 has
  several (server-fn stubs, `/__mountHydrate`, `/__serverLoad/*`, SPA nav fetch, `/_scrml/log`) —
  filed as g-impl1-runtime-fetch-follows-base-href-s473 (S471 policy: not fixed).
- Test infra: `server-artifact-harness.js` `bridge` takes an absolute URL (checks it is the page's
  origin, passes the path to the server); `server-call-runtime.test.js` serves its page from
  `http://localhost/` (happy-dom starts at about:blank, where the runtime now refuses to send) and
  asserts the absolute target. Every fetch-stubbing slice-m4 file passes run in its own process.
- Chromium, head (same probe): `<base href=(@c)>` / `HREF=@c` → E-ATTR-BASE-HREF; STATIC
  cross-origin `<base>` → `self:POST /_scrml/call/1` (was `evil:OPTIONS`). Unchanged and filed:
  meta refresh (navigates to evil — g-boot-meta-refresh-content-from-data-s472 raised to MED with
